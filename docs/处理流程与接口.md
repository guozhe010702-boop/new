# 处理流程与接口

## 实时链路

```text
IMX415与ISP → GStreamer V4L2采集NV12 → videorate限采样30FPS
 → appsink单缓冲取最新样本 → 根据实际colorimetry转换RGB
 → 最新帧槽一张 → RGA缩放或ROI裁剪 → RKNN模型
 → 拒绝乱序结果的最新结果槽 → 后处理与透明文字HUD
 → DRM双缓冲与真实翻页 → HDMI
```

相机使用已有RKAIQ服务；工程不创建第二个ISP控制器。相机与现有MPP预览共用互斥锁，不能同时采集同一节点。

当前适配器显式映射、复制NV12图像并生成RGB；`--capture-memory dmabuf`只改变GStreamer采集内存模式，不代表RGA/RKNN全链路零拷贝。RGA预处理内部通过私有DMA32缓冲共享像素，但CPU仍进行输入写入和输出读取。这些操作计入预处理与取样后帧龄。

颜色解释来自GStreamer实际caps。BT709 full-range使用CPU范围映射与已验证RGA709转换；BT2020或其他已支持的矩阵使用CPU矢量矩阵转换，RGA继续负责模型尺寸缩放；未知矩阵直接报错，不猜测颜色。当前板端V4L2格式曾报告BT2020 full-range，因此不能始终硬编码BT709。硬件测试覆盖RGA黑白红、518宽度对齐和CPU BT2020红色转换；这不是相机光学校色。

## 帧与模型接口

`Frame`持有递增ID、appsink取样的单调时间及引用计数RGB矩阵。尺寸、stride和内存格式由`cv::Mat`描述，原始GStreamer样本在同步转换完成后释放。模型不能引用已经归还给采集驱动的NV12指针。

`Model`只接收连续、尺寸匹配的UINT8 RGB。图内保存mean/std，RKNN负责输入类型转换。构造时查询模型输入输出，检查单图像输入、三通道、芯片Runtime及绑核结果。常规路径请求FP32输出，复制后释放SDK引用；优化超分路径请求逻辑NCHW FP16特征，在SDK输出有效期内完成CPU重建为FP32 RGB，再释放引用。每个推理线程有独立Model上下文和RGA缓冲。

`Latest`容量始终为一，原始帧积压时替换旧等待帧；多上下文结果按ID拒绝旧结果覆盖新结果。替换计数与实际处理计数分开。已取得的在途推理可以完成，但跟踪器只接收递增帧ID。

## 算法后处理

YOLO使用Rockchip九输出DFL图，按三尺度解码、类别内NMS和letterbox逆变换恢复原图框。ByteTrack保留高低置信度两阶段关联，每个类别独立跟踪；Kalman预测时间步按真实取样间隔调整。超过一秒的间断重建跟踪状态，避免错误跨越计数。旧越线状态与已移除轨迹定期清理，连续运行不会无限累积历史ID。

深度采用518方形letterbox部署策略，RGB按ImageNet参数归一化。输出去掉padding并恢复采集尺寸，保存浮点相对深度。伪彩仅做可视化，逐帧归一化不表示固定物理距离；深度值不能直接传给需要米制坐标的避障控制器。

实时超分提取256方形ROI，运行通用场景SRVGG轻量×4模型，与双三次插值并排显示。离线大图使用40像素halo保证有效区域有足够感受野，边缘块贴齐原图边界，输出浮点值裁剪至合法显示范围后保存。

优化实时超分使用`fp16-trunk.rknn`保留原学习型卷积，输出48×256×256；`common/sr_tail.hpp`完成PixelShuffle×4、nearest输入残差与FP16舍入，逻辑输出仍为3×1024×1024。以`--sr-tail cpu`选择，以`--sr-tail npu`退回原完整模型。离线`sr_tiled`默认继续使用原完整模型，不能直接把trunk模型交给旧三参数入口。当前优化不等同于整张4K实时超分，逐层证据及精度、时延对比见[NPU第三轮报告](NPU瓶颈定位与第三轮优化.md)。

## 显示与监督

DRM使用两个XRGB8888 dumb buffer。当前扫描缓冲不被CPU修改；写入另一个缓冲后提交page flip，收到完成事件才复用旧缓冲。可视化是CPU合成与显式显示拷贝，不能称为解码DMA-BUF直显。HUD直接画在合成视频上，文字有描边、不填黑色背景，采用英文指标名以避免字体依赖。

监督器保存原V4L2格式、原桌面运行状态和Xrandr布局，使用临时systemd单元和ExecStopPost恢复。退出时先结束工作线程，再释放显示与推理上下文，最后恢复设备。异常启动、超温72摄氏度、显示失败和无结果超时均会结束本次运行。物理拔线与断电不等同于软件注入测试。

## 文件作用

| 文件或目录 | 作用 |
|---|---|
| `common/main.cpp` | 参数、工作线程、三算法后处理、HUD、结果与计时 |
| `common/camera.cpp` | GStreamer采集、样本生命周期、颜色解释 |
| `common/preprocess.cpp` | DMA32缓存同步、RGA缩放、颜色转换及对齐 |
| `common/model.cpp` | RKNN生命周期、张量检查、浮点输出与YOLO解码 |
| `common/sr_tail.hpp` | FP16特征直读、NEON像素重排、原图残差与逻辑输出重建 |
| `common/npu_profile.cpp` | 独立API分段计时、原生张量属性、逐层详情 |
| `common/sr_tail_check.cpp` | 完整FP16 RKNN与CPU尾部的50图独立对照 |
| `common/display.cpp` | HDMI资源发现、双缓冲和翻页事件 |
| `common/sr_tiled.cpp` | 离线整图×4超分和拼接 |
| `common/batch.cpp` | 一次加载模型后批量输出真实NPU张量 |
| `common/tests.cpp` | 队列乱序、量化直方图、跟踪遮挡和越线计数测试 |
| `common/hardware_tests.cpp` | 真实RGA及颜色、stride检查 |
| `tools/control.py` | 手动启停、资源遥测、互斥与设备恢复 |
| `tools/convert.py` | 官方权重导出ONNX及RKNN，保存数值检查和散列 |
| `tools/convert_sr_trunk.py` | 提取相同权重卷积图、ONNX等价检查、转换FP16 trunk |
| `tools/npu_benchmark.py` | 有界独占NPU诊断，使用准备好的模型尺寸图片 |
| `tools/prepare_data.py` | 分离校准/验证集并生成固定模型输入 |
| `tools/quality.py` | ONNX、板端FP16和INT8输出的精度对比 |
| `tools/suite.py` | 有限时长串行调度对比、重复测试和长测 |
| `tools/lifecycle.py` | 真实模型及显示下的启停、异常退出检查 |
| `tools/check_seams.py` | 拼接输出与整图PyTorch参考的接缝比较 |
| `tools/fetch_models.py` | 下载并核验原始官方权重 |
| `tools/build_board.sh` | 防止覆盖活动进程并构建、运行检查 |
| `vendor` | 固定版本第三方算法源码与许可证 |
| `runtime` | 私有RKNN和RGA库及头文件 |

ByteTrack源码在保留MIT声明的前提下增加时间步接口、过程噪声时间缩放、历史清理和异常处理。部署中不运行上游的NCNN示例主程序。
