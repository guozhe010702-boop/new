# 第四轮：NPU候选实测与异步保存优化

日期：2026-11-25。已重新连接开发板，完成8组深度NPU候选的板端交替对比，以及异步保存的真实相机、HDMI和退出恢复测试。**本轮采用异步保存；深度NPU候选均未替换默认模型。**

## 已落地的改变

原`common/main.cpp`在显示线程同步压缩、写入深度YAML、PNG和原始张量，单次保存约1.9秒，导致首次显示和周期保存时停顿。现改为`common/async_writer.hpp`后台保存：一个正在写入的任务，加一个最新待写任务；新任务覆盖旧待写任务，不等待磁盘。保存线程nice=10，图像、张量由共享所有权保活，退出时等待待写任务完成。

`--save-every 0`在三个推理项目中现在确实关闭图像和张量保存；CSV、遥测和摘要仍保留。正数N表示每N个已显示结果提交一次保存，包含首次结果。保存拥堵时会跳过旧的待保存样本，因此文件编号可有间断，不适合作为完整逐帧录制接口。采集专用capture模式沿用原采样保存逻辑，不在此改动范围。

summary.json新增`save_jobs_submitted/written/replaced/failed/discarded`及保存耗时统计。全部任务归类守恒：提交=完成+被替换+失败+丢弃。写入失败通过主流程报错并由监督器恢复设备；失败任务可能留下部分文件，应按失败日志识别。

## 真实HDMI A/B结果

同一板子、同一启动周期，1080p30相机、1080p60 HDMI、Depth Anything V2 Small 518×518原FP16、单上下文mask7。ABBA各30秒，`save_every=10`，用较频繁保存暴露停顿。表中为两轮同类指标的算术平均；不是合并样本的分位数。

| 指标 | 旧版同步保存 | 新版异步保存 |
|---|---:|---:|
| 首次显示帧龄 ms | 2682.10 | 823.97 |
| 翻页间隔P95 ms | 2591.54 | 741.39 |
| 稳态处理 FPS | 1.29 | 1.41 |
| 进程CPU，单核100%口径 % | 63.17 | 69.44 |
| 峰值RSS MiB | 270.99 | 286.19 |

首次显示帧龄减少约69.3%，翻页间隔P95减少约71.4%。模型调用P50仍约710ms，不能把此收益描述成NPU推理提速。默认save_every=300时主要改善首次显示和低频保存长尾，日常稳态FPS提升幅度不能直接套用上述save_every=10结果。异步保存增加有限的图像驻留和并行CPU工作，表中列出对应资源成本。

- 真实IO失败：预先在测试专用输出位置建立同名目录，令张量写入失败；程序错误退出，save_jobs_failed=1，桌面和设备恢复成功。

内部帧龄为appsink取样到HDMI翻页；翻页间隔根据每帧取样时间加帧龄计算。未做光学测量，不包含曝光、取样前排队和屏幕响应。本报告是三个视觉算法工程的1080p采样测试，不能当作mpp_decode_bench的4K60编解码验收。

## 深度NPU候选结果

原模型注意力算子约占逐层时间69%，CPU Resize约占10%。每个候选采用原权重与518输入，单上下文mask7，ABBA各12次有效调用、另3次预热；逐层采样另行执行，避免把性能分析开销混入计时。温度低于65℃预算。正数表示调用耗时下降，负数表示变慢。

| 候选 | 当组原模型 ms | 候选 ms | 耗时下降 |
|---|---:|---:|---:|
| Flash配置 | 649.63 | 650.32 | -0.11% |
| 每组2个注意力头 | 648.88 | 662.53 | -2.10% |
| 每组1个头加Flash | 650.00 | 662.98 | -2.00% |
| 矩阵形式Resize | 650.52 | 1178.91 | -81.23% |
| Gather形式Resize | 651.18 | 685.41 | -5.26% |
| 自动INT8/FP16混合精度 | 649.80 | 639.22 | +1.63% |
| GPU回退标志 | 650.91 | 650.12 | +0.12% |
| 隔离Runtime 2.5.0 | 651.15 | 651.13 | +0.00% |

这些候选没有达到预设5%收益门槛，因此都不采用。Flash参数被接受不等于出现硬件加速；拆分注意力头也没有实现有效多核提速。矩阵Resize计算量增加后明显变慢，Gather版本也没有收益。Runtime 2.5.0只在隔离目录下测试，系统库和项目默认2.3.2均保留。

等价图候选使用原FP32 ONNX两张样本比对与权重逐项核对；第一版矩阵Resize曾因坐标计算顺序造成两处像素误差而拒绝，修正为float32坐标后再编译、测量。自动混合精度使用194张校准图，两个模拟器样本与ONNX秩相关为0.99233和0.99672，但板端仅快1.63%；未执行完整50图质量验收或实时候选验收，不宣称量化质量通过。

RK3588的exSDPAttention不支持多核联合，见[官方2.3.2算子手册](https://github.com/airockchip/rknn-toolkit2/blob/v2.3.2/doc/05_RKNN_Compiler_Support_Operator_List_V2.3.2.pdf)RK3588章节3.2.78。自动混合精度参数见[官方Python API手册](https://github.com/airockchip/rknn-toolkit2/blob/v2.3.2/doc/03_Rockchip_RKNPU_API_Reference_RKNN_Toolkit2_V2.3.2_EN.pdf)。后续若要数量级提升，优先评估适合RK3588算子的轻量深度网络或蒸馏学生模型，并建立完整验证基线；继续堆上下文或更改mask不能保证解决注意力瓶颈。

## 代码、数据与运行

- `common/main.cpp`：提交保存任务、保持图像生命周期、汇总任务计数与错误。
- `common/async_writer.hpp`：有界异步写入器。
- `common/async_writer_tests.cpp`：保存队列和失败传播检查。
- `tools/probe_depth_attention.py`、`probe_depth_graph.py`、`probe_depth_hybrid.py`：独立候选构建与数值初筛。
- `tools/benchmark_depth_candidate.py`：板端ABBA和逐层采样；混合精度需显式`--allow-mixed-experiment`；不会选定默认模型。
- `docs/round4-validation.json`：可审阅的指标、哈希及验证收据；完整本地日志在`state/npu-candidates/*-board-20261125`，Windows与板端均保留。
- 部署打包排除`.git`和`state`，避免夹带运行状态或实验模型，保留新的异步写入测试程序。

板端工程目录：`/userdata/av_dev/advanced algorithms`。现有start/stop/status脚本继续可用，以下命令在板端root终端执行：

```bash
cd "/userdata/av_dev/advanced algorithms"
# 仅实时查看深度，不保存图像和张量
bash depth_anything_v2/start.sh --save-every 0
bash depth_anything_v2/status.sh
bash depth_anything_v2/stop.sh
# 需要采样留档时选择间隔，例如每300个显示结果
bash depth_anything_v2/start.sh --save-every 300
```
