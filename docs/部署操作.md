# 部署操作

当前开发板已部署，无需重复安装。优先使用根目录README中的启动和停止命令。默认不开机自启，测试结束后停止预览并恢复桌面。

## 新板准备

新板需要兼容的RK3588 BSP、IMX415驱动与IQ、RKAIQ服务、NPU驱动、GStreamer以及HDMI。当前验证组合为内核5.10.110、NPU驱动0.9.8、私有RKNN Runtime2.3.2。系统旧版RKNN库不覆盖，程序通过私有库路径运行。

复制部署压缩包至新板的`/userdata/av_dev`，确认目标目录没有需要保留的同名旧工程，再解压。不要直接覆盖运行中的程序或不同版本的模型。

```bash
cd /userdata/av_dev
tar -xzf /userdata/advanced-algorithms-rk3588.tar.gz
cd "advanced algorithms"
python3 tools/preflight.py --verify-package
```

若缺少系统开发依赖，执行`bash tools/install_system_deps.sh`，安装后再预检。仅二进制运行时也需要OpenCV、GStreamer与libdrm等共享库。预检只检查环境，实际模型与HDMI兼容性仍在启动时验证。

板端默认使用包内ARM64可执行程序，修改源码后先停止，再运行`bash tools/build_board.sh`。构建脚本会拒绝替换仍在执行的本工程二进制。

## 手动控制

每个项目都有start、stop、status、benchmark脚本。三个项目共用设备，先停止上一个再启动另一个；图像和视频离线测试也由同一监督器执行，避免并发争用NPU影响计时。

```bash
bash yolo11_bytetrack/start.sh
bash yolo11_bytetrack/status.sh
bash yolo11_bytetrack/stop.sh
bash depth_anything_v2/start.sh
bash depth_anything_v2/stop.sh
bash real_esrgan/start.sh
bash real_esrgan/stop.sh
```

查看日志：`journalctl -u advanced-algorithms.service -n 80 --no-pager`。若停止后设备未恢复，先确认本工程原生进程已经停止，再执行`python3 tools/control.py restore`并检查restoration.json。不要对仍在运行的设备强行恢复格式。

## 基准测试

```bash
bash yolo11_bytetrack/benchmark.sh --output "results/yolo-new-test"
python3 tools/suite.py --output "results/new-qualification"
```

benchmark默认300秒，suite默认每个模型三轮300秒与1800秒连续测试，并先比较三种NPU调度。suite会多次切换桌面和预览，须保留相机和HDMI。输出目录必须是新的。缩短参数可用于调试，但短测不会发布stability_validated为true的推荐配置。

项目recommended.json分别记录精度、上下文数、核掩码、完整测试时长、实测FPS和目标是否达到。稳定运行通过不等于达到深度20FPS或超分40ms目标。

## 文件迁移

运行包包含源码、ARM64程序、私有运行库、RKNN模型与精简报告，不把逐帧大批张量、相机校准图或16K输出图放进部署包。原始实验结果仍在Windows和板端results目录保留。转换所需原始权重与ONNX保存在Windows源码目录，下载恢复脚本会核验官方权重SHA256。

新板设备节点、颜色矩阵、显示模式和驱动版本若不同，需要重新验证；本包不会通过更换系统库、修改内核或猜测颜色来掩盖不兼容。
